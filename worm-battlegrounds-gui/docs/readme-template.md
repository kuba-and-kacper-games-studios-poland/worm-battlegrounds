# Unit READMEs

Each unit of UmeGui has a `_meta/README.md` next to its code: what it is, what it exposes and how it is used. It is the only place a unit is described; nothing describes a module above `local Module = {}`. The rule is `.claude/rules/luau/readme.md`; `/readme <folder>` writes or refreshes one from the code.

`.md` files never sync into Studio. No `_meta` folder goes directly inside `src/themes/` or a theme's `Styles/` (the engine requires every child there), and none inside the generated `src/engine/Libs/Mirror/`.

## Units

| README | Covers |
| --- | --- |
| `src/engine/_meta/README.md` | The engine |
| `src/engine/Controls/_meta/README.md` | Every control, one section each |
| `src/themes/<Theme>/_meta/README.md` | One theme |
| `src/guis/<Set>/<Gui>/_meta/README.md` | One gui (a gui that is a single file becomes a folder module first: `<Gui>/init.lua`) |
| `src/guis/Plugin/_meta/README.md` | Every plugin widget, one row each. Each ume-rbx tool's README describes what it does with its widget |

## Engine

1. `# UmeGui` and an overview: what the engine builds and who calls it (the Gui tool, plugin widgets, game guis via export).
2. `## API`: every function `init.lua` returns, as `Function`, `Returns`, `What it does`. Mark the host API (the functions the plugin calls on a place's UmeGui) and point to Host API in `gui/format.md`.
3. `## Engine`: one row per `Engine/*` module and `Primitives.lua`: what it owns.
4. `## Libs`: `Component`, `Runtime`, `Scope`, `Sound`, and `Mirror` (generated by `scripts/Sync.ps1 Libs` from the paired game's framework folder; what it holds).
5. `## Version`: where the version lives and when it is bumped (`gui/repo.md`).

## Controls

A short overview, then one `## <Control>` per control in `src/engine/Controls/`:

- what it is, in one or two sentences;
- the structure it is built from (`ctx.Pressable`, `ctx.Surface`, a `ScrollingFrame`, …);
- its handle fields beyond `Instance` (`Button`, `Field`, `Viewport`, …) and what they are;
- its style file, `Styles/<Control>.lua`.

Node keys, params, signals and variants stay in the control catalog of `gui/format.md`; each section links there instead of repeating them.

## Theme

1. `# <Theme>` and an overview: what it looks like and whether it extends another theme.
2. `## Tokens`: the token groups in `Tokens.lua` and what each is for.
3. `## Styles`: the style files and the variants each adds.
4. `## Controls`: the theme's own controls, if it has a `Controls/` folder.
5. `## Generated`: `Gamepad.lua` and where it comes from.

## Gui

1. `# <Gui>` and an overview: what the player or Studio user sees and does with it.
2. Facts table: `Path` (`"Hud/Inventory"`), `Kind` (when not `Default`), `Theme`, `Modes`, `Devices`, `Export` (the exported gui's name and properties).
3. `## Elements`: every `U_` element and the `S_` elements under it, with the control and what game code does with it.
4. `## Prefabs`: every `PREFAB | Name` template, its parent and its `S_` elements.
5. `## Driven by`: the game module (or plugin tool) that builds or finds this gui and what it calls.
6. `## Preview`: what the `Preview` module's settings and buttons do, when it has one.
7. `## Integration`, for every gui a game module or plugin tool drives (every System gui): what the next person needs to plug it into a game without reading the code.
   - `### Setup`: how it is exported (and its name), which Ids and prefab names a restyled copy must keep, the modules that drive it and the settings, tags, attributes, sounds and gradients they need.
   - `### Input`: one row per action, with its mouse and keyboard keys, touch, gamepad buttons (Xbox / PlayStation) and where each is bound. Say "None" in a sentence when it takes no input.
   - `### Looks`: one row per interaction state (rest, hover, press, selected, equipped, favourite, opening): the element, and the exact colours, gradients, transparencies, scales and tweens (time, style, direction).
